# تقرير التحقق — 29 سبتمبر 2026

تم تنفيذ التحقق على Windows وNode.js 24 باستخدام PostgreSQL فعلية محلية (embedded-postgres)، وليس قاعدة بديلة أو بيانات ثابتة في الواجهة.

## اختبارات التكامل

ست مجموعات اختبارات نجحت:

1. المصادقة: دخول صحيح وخاطئ، حماية المسارات، Origin/CSRF، كوكي HttpOnly، خروج وإبطال الجلسة.
2. العملاء: إنشاء وقراءة وتعديل وحذف منطقي، ملكية المبيعات، إعادة الإسناد وثبات المنشئ، رفض عمليات مشتري الإعلانات برمز 403.
3. التقارير: تجميع PostgreSQL، مجموع 0.10 + 0.20 دون خطأ عشري، مجموع المصادر والمبيعات، فلاتر مركبة، حدود يوم القاهرة، استبعاد المحذوفين، عدم وجود بيانات العملاء في الرد.
4. الإدارة: إنشاء المستخدمين، إنشاء وتعديل وتعطيل المصادر والحقول، حفظ القيم التاريخية، منع المصدر المعطل في الإدخال الجديد، إبطال الجلسة عند تعطيل الحساب.
5. تسلسل القبول: إنشاء مبيعات ومشتري إعلانات ومصدر وحقل، إضافة العميل وتأكيده وملاحظة تحديث التقرير، إعادة إسناده لموظف آخر، تحقق المنشئ والمسؤول، دخول مشتري الإعلانات وفحص تقاريره ومحاولات API المحظورة، تعطيل الحقل والمصدر وفحص القيم القديمة، واختبار فلاتر التاريخ والمصدر والموظف والحالة مجتمعة.

6. كلمات المرور: رفض تجاوز 72 بايت بما يشمل الحروف العربية لتفادي اقتطاع bcrypt الصامت.

مجموعات الاختبار تحتوي تأكيدات متعددة؛ عدد «6» هو عدد السيناريوهات المجمعة، وليس عدد التأكيدات الفردية.

## المتصفح

Chrome آلي، سطح مكتب 1440×1000 وهاتف 390×844:

- تسجيل الدخول والخروج بأدوار المدير والمبيعات والإعلانات.
- تحميل Dashboard من PostgreSQL ورؤية التقارير.
- فتح نموذج إضافة العميل ومراجعة حقوله.
- فتح صفحات المستخدمين والمصادر والحقول.
- إضافة عميل من الهاتف والبحث عنه وعرض تفاصيله.
- عدم امتداد الصفحة أفقيًا على الهاتف (الجداول لها تمرير داخلي).
- منع بيانات العملاء من واجهة مسؤول الإعلانات ومن API.
- لم تُرصد أخطاء JavaScript غير معالجة في السيناريو الناجح.
- تمت مراجعة صور الكمبيوتر والهاتف بصريًا، وإيقاف حركة الرسوم لضمان ظهور الأرقام فورًا.

## البناء والأمان

- توليد Prisma وفحص TypeScript وبناء Vite نجحت.
- فحص npm audit بعد تحديث اعتماديات Prisma الفرعية: صفر ثغرات معروفة حسب قاعدة npm وقت الفحص. هذا ليس ضمانًا بعدم وجود ثغرات مستقبلية.
- صلاحيات كل مسار محمية في الخادم، مع مخارج بيانات محددة لتجنب إرجاع passwordHash أو حقول العملاء في التقارير.
- لا توجد أسرار ثابتة أو كلمة مرور demo ثابتة في المصدر.
- مخطط Prisma والترحيل الأول وملف قفل npm محفوظة في المشروع.

## حدود ما تم التحقق منه

لم يتم نشر التطبيق على Hostinger أو ربط `crm.mts-makka.com` أو اختبار HTTPS الحقيقي هناك. إعداد PostgreSQL الإنتاجية والأسرار والنطاق والنسخ الاحتياطي واختبار الاستعادة مطلوب عند النشر.

منعت بيئة الجهاز كتابة برامج Node داخل Documents، لذلك حُفظ المصدر في مجلد المشروع، ونُفذت الاختبارات في نسخة تشغيل ضمن مساحة Codex المسموح بها. لا توجد تغييرات في إعدادات حماية Windows أو موقع WordPress.
