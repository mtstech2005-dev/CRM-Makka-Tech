# MTS Lead Tracking CRM

تطبيق عربي RTL مستقل لمتابعة العملاء، مبني بـ React وTypeScript وExpress وPostgreSQL وPrisma. لا يعتمد على WordPress أو قاعدة بيانات المتجر.

## التشغيل

يتطلب Node.js 22 أو 24 وPostgreSQL. من مجلد المشروع:

```sh
npm ci
npm run db:local
```

اترك قاعدة البيانات المحلية تعمل. في نافذة أخرى:

```sh
npm run db:migrate
npm run db:seed
npm run dev
```

افتح عنوان `FRONTEND_URL` الموجود في `.env`. المساعد المحلي ينشئ هذا الملف بأسرار عشوائية. لقاعدة بيانات قائمة، استخدم `.env.example` واضبط القيم بنفسك بدل `db:local`.

حساب المدير التجريبي: `admin@mts-makka.com`. المبيعات: `ahmed@mts-makka.com` و`mohamed@mts-makka.com` و`mahmoud@mts-makka.com`. مسؤول الإعلانات: `media@mts-makka.com`. كلمة المرور المشتركة للاختبار هي قيمة `DEMO_PASSWORD` في `.env` الخاص بك. السكربت يرفض العمل على الإنتاج أو قاعدة تحتوي مستخدمين.

## ما يتضمنه التطبيق

- جلسات آمنة بكوكي HttpOnly، وصلاحيات ADMIN وSALES وMEDIA_BUYER وSHIPPING من الخادم.
- إدخال العملاء والبحث والترقيم والفلاتر من PostgreSQL، مع حذف منطقي للمدير.
- أسعار Decimal، وهوية منشئ العميل ثابتة عند إعادة الإسناد.
- تقارير مصادر وحالات ومبيعات بقيم محسوبة في قاعدة البيانات، وفترات بتوقيت القاهرة (بداية الأسبوع السبت).
- حسابات ومصادر وحقول مخصصة تديرها الإدارة. تعطيل السجلات لا يمحو تاريخ العملاء.
- واجهة متجاوبة، Cairo محلي، نماذج عربية، حالات تحميل وخطأ ونجاح وتأكيد الحذف.

## التحقق والبناء

```sh
npm run build
npm test
```

`npm test` يستخدم اتصال `.env` ويجب تشغيله على قاعدة تطوير محلية فقط. الاختبارات تنشئ سجلاتها المحددة وتمسحها بعد التحقق. لا تستخدم قاعدة الإنتاج. اختبار المتصفح الإضافي: `node --import tsx tests/browser-check.ts`، بعد تشغيل الخادم وseed المحلي، ويتطلب Chrome. الاختبار يضيف عميلًا تجريبيًا ويُزيله بعد التنفيذ.

اختبارات API تغطي المصادقة وCSRF، ملكية العملاء، إعادة الإسناد، رفض مشتري الإعلانات، الحساب العشري، حدود اليوم في القاهرة، الفلاتر المركبة، التاريخ المحفوظ عند التعطيل، وسيناريو القبول.

## الملفات

- `src/`: واجهة React والأنماط.
- `server/`: API والتحقق والصلاحيات والتقارير.
- `prisma/`: المخطط والترحيلات وseed.
- `scripts/`: قاعدة البيانات المحلية وإنشاء المدير الأول.
- `tests/`: اختبارات التكامل والمتصفح.
- [دليل النشر](docs/DEPLOYMENT.md): تجهيز Hostinger والنطاق وHTTPS وPostgreSQL.

## حدود الإصدار

إدخال يدوي فقط. لا مزامنة WooCommerce أو WhatsApp، ولا حسابات أو دفع. أضيف تسجيل المصروفات الإعلانية يدويًا وتقارير الحملات والإعلانات. التقارير تعرض قيمة الطلبات، وليست الإيراد المحصل. لا توجد استعادة حذف في واجهة المستخدم؛ الحذف منطقي داخل قاعدة البيانات. حذف حقل إضافي يؤرشفه، ويظل ظاهرًا ضمن بيانات العملاء التاريخية.

للنشر في Hostinger Cloud، استخدم خدمة PostgreSQL خارجية تدعم TLS أو VPS منفصلًا. الاستضافة الحية وربط النطاق والأسرار والنسخ الاحتياطي مسؤوليات خطوة النشر؛ لا ينفذها المشروع تلقائيًا.


## تحديث الحملات والشحن

أضيفت إدارة Meta Ads وGoogle Ads والمصروفات اليومية، وربط الحملات والإعلانات بالعملاء، وحالتا الطلب والشحن، ودور مسؤول الشحن. راجع [تفاصيل الترحيل والصلاحيات والحسابات](docs/CAMPAIGNS-SHIPPING.md).

المدير يضيف قائمة الشحن الأصلية من «حالات الطلب والشحن»، ثم ينشئ حسابًا بدور SHIPPING من «المستخدمون». لا توجد كلمة مرور شحن افتراضية ولا متغيرات بيئة جديدة.
